# Mosaic ERP - conversational retail ERP architect

[Product page](https://hearthplug.github.io/mosaic-erp/) · [Current release v1.1.0](https://github.com/Hearthplug/mosaic-erp/releases/tag/v1.1.0) · [Docker Hub](https://hub.docker.com/r/hearthplug/mosaic-erp) · [Deployment guide](docs/DEPLOYMENT.md) · [Architecture and limits](ARCHITECTURE.md)

Mosaic ERP interviews a retail owner in plain language and compiles the answers into a tailored, versioned ERP blueprint. Navigation, KPIs, modules, workflows, roles, terminology, and source-linked tax configuration change with the business model. It supports 22 jurisdiction packs and use cases including grocery, fashion, electronics, pharmacy, beauty, specialty retail, multi-store, omnichannel, credit, batch/expiry, serial/warranty, and services.

Mosaic is source-available under MIT. It creates ERP blueprints and configuration, not a financial ledger, accounting replacement, tax filing, certification, or legal/tax advice.

## Try locally

```bash
python3 install.py
python3 app.py
```

Open `http://localhost:8000`. Python 3.10+ is the only prerequisite. This SQLite path is for evaluation and simple single-node use. Protect the one-time `mosaic-workspace.key` generated by the installer.

See the live [Mosaic ERP product page](https://hearthplug.github.io/mosaic-erp/) for screenshots, supported use cases, deployment choices, and verified release links.

## Production deployment

Production Compose and Kubernetes/Helm paths use an external PostgreSQL service. They do not bundle production credentials or claim to supply managed database HA.

### Docker image

```bash
docker pull hearthplug/mosaic-erp@sha256:c63f4ae7275a260397350e553fded8f6eba5458969753eb94628c2cbf51e7a02
```

The signed multi-architecture image supports `linux/amd64` and `linux/arm64`. GHCR is also available at `ghcr.io/hearthplug/mosaic-erp@sha256:480e9ba790107cd5b43859087e4f1468f9712e9d8ba9a84d2d4edcaefa4018e3`.

### Docker Compose with PostgreSQL

```bash
export MOSAIC_DATABASE_URL='postgresql://mosaic_app:...@db.example.com:5432/mosaic?sslmode=verify-full'
docker compose up -d --build
```

### Kubernetes / Helm with PostgreSQL

```bash
helm upgrade --install mosaic deploy/helm/mosaic-erp --namespace mosaic --create-namespace \
  --set image.repository=hearthplug/mosaic-erp \
  --set image.digest=sha256:c63f4ae7275a260397350e553fded8f6eba5458969753eb94628c2cbf51e7a02 \
  --set database.secretName=mosaic-db \
  --set database.migrationSecretName=mosaic-db-owner \
  --set networkPolicy.databaseCIDR=10.20.0.0/24
```

The chart includes two replicas, a separate migration Job and credential, probes, resource bounds, pod security, NetworkPolicy, topology spread, PDB, and optional HPA. Operators remain responsible for DNS/TLS, secret management, managed PostgreSQL HA/PITR, restore drills, cluster failover and capacity tests, a selected/tested OIDC provider, monitoring, and an independent penetration test before real financial-data use.

Read the [deployment guide](docs/DEPLOYMENT.md) and [PostgreSQL operations guide](docs/POSTGRESQL.md).

## How Mosaic differs

Most conversational ERP assistants query or operate software that has already been configured. Broad modular ERP platforms still need implementation work to translate a retailer's operating model into modules, roles, fields, workflows, and controls. Mosaic targets that earlier translation step. Its deterministic rules compiler remains the safety boundary, while the conversation gathers facts and previews changes.

Mosaic is not positioned as a complete alternative to mature accounting or transaction-processing suites. It produces working, explainable ERP blueprints and a hardened configuration service that can feed later implementation.

## Use cases

- **Grocery and pharmacy:** batch/expiry controls, inventory KPIs, jurisdiction-specific configuration questions
- **Fashion and specialty retail:** variants, stores, channels, returns, team roles, and tailored terminology
- **Electronics:** serial/warranty workflows and omnichannel operations
- **Services and beauty:** appointments, service workflows, staff roles, and retail inventory together
- **Multi-store retail:** versioned tenant workspaces, role-based access, audit history, idempotent writes, and rollback

Tax packs cover India, UAE, Singapore, China, Vietnam, Malaysia, UK, USA, Canada, EU, Australia, New Zealand, Japan, South Korea, Saudi Arabia, South Africa, Brazil, Mexico, Indonesia, Philippines, Thailand, and Switzerland. Each pack carries source links, dates, and warnings for facts that cannot be safely assumed.

## API and architecture

Public/stateless endpoints include health, readiness, metrics, dynamic questions, live preview, final configuration, export, and conversational compliance control. The authenticated workspace API supports versioned configuration, optimistic concurrency, roles, key/session revocation, audit history, rollback, export, and confirmed erasure.

SQLite uses WAL for local evaluation. PostgreSQL adds bounded pooling, migrations, database-enforced tenant isolation, concurrent replica-safe writes, and shared application state. See [ARCHITECTURE.md](ARCHITECTURE.md), [SECURITY.md](SECURITY.md), and [OIDC.md](OIDC.md).

## FAQ

### Is Mosaic ERP an accounting system?
No. Mosaic creates versioned ERP blueprints and configuration. It is not a financial ledger or accounting-system replacement.

### Does Mosaic calculate or file taxes?
No. Tax packs are source-linked configuration blueprints, not filings, certification, legal advice, or tax advice. Confirm item classification and current rules with a local professional.

### Can I run Mosaic without Docker or an account?
Yes. The local evaluation path needs Python 3.10+ and two commands. It stores data in SQLite on the same machine.

### What should I use for production?
Use the external-PostgreSQL Compose or Kubernetes/Helm path, then complete the operator-owned infrastructure and security work listed above. Source and CI evidence do not prove your cluster's failover, capacity, backups, or restore process.

### Is the container signed and scanned?
Yes. The current amd64/arm64 images have SBOM/provenance attestations and keyless cosign signatures. The release workflow passed the configured HIGH/CRITICAL Trivy gate.
