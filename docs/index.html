Three deployment paths.

Use local Python for the fastest evaluation, Docker Compose for a hardened single host, or Helm for cluster packaging. All three run the same current SQLite build.

Local Python

python3 install.py
python3 app.py

Python 3.10+ only. Best for evaluation and development.

Docker Compose

docker compose build --pull
docker compose up -d

Non-root, read-only runtime, persistent volume, health probe, resource bounds and Caddy HTTPS path. Builds locally until a registry image is published.

Kubernetes / Helm

helm upgrade --install mosaic
deploy/helm/mosaic-erp

StatefulSet, probes, limits, PVC, Ingress/TLS and disruption budget. Linted and rendered; cluster runtime validation is still required.

Hardened single-node posture, stated plainly.

SQLite WAL, transactional writes, hashed API keys, named users, expiring sessions, persistent rate limits, a strict external-asset CSP, tenant isolation, roles, idempotency, versioning, backups, secure defaults, observability, and privacy controls are implemented and release-tested.

What current main verifies

79 automated tests plus live-server checks cover customization, 22 packs, JSON export, compliance previews and rollback, migrations, isolation, API-key and named-user roles, session expiry/revocation, persistent rate limiting, strict CSP assets, idempotency, versions, audit, backup/restore, recovery, and privacy controls.

Honest limits

  • Not a financial ledger or accounting-system replacement.
  • Local mode uses HTTP on loopback; Docker/Compose and Kubernetes/Helm artifacts are source-ready, with runtime verification gated by CI and a real cluster.
  • SQLite remains single-node. No PostgreSQL adapter or true HA is implemented.
  • Local named users and sessions exist; OIDC is specified but no provider adapter is configured.
  • No registry image is published yet. Real DNS/TLS, encrypted offsite backups, failover operations, and restore rehearsal remain operator work.
  • No independent security audit has been performed.
