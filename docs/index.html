Three deployment paths.

Use local Python with SQLite for the fastest evaluation. Production Docker Compose and Helm use an external PostgreSQL service with operator-owned TLS, secrets, backups, and failover.

Local Python

python3 install.py
python3 app.py

Python 3.10+ and zero external services. Best for evaluation and simple single-node use.

Docker Compose

export MOSAIC_DATABASE_URL=...
docker compose up -d --build

Non-root, read-only application with a health probe, resource bounds, Caddy HTTPS, and external PostgreSQL. The Compose file does not create production credentials.

Kubernetes / Helm

helm upgrade --install mosaic
deploy/helm/mosaic-erp

Two-replica Deployment, separate migration Job, probes, limits, NetworkPolicy, topology spread, PDB, optional HPA, and external PostgreSQL. Cluster failover and PITR still require operator validation.

Production database path, stated plainly.

SQLite remains the simple evaluation path. PostgreSQL adds bounded pooling, concurrent replica-safe writes, database-enforced tenant isolation, migrations, and shared application state while preserving roles, idempotency, audit, and version history.

What current main verifies

82 automated source tests plus live-server checks cover customization, 22 packs, JSON export, compliance previews and rollback, migrations, isolation, API-key and named-user roles, session expiry/revocation, persistent rate limiting, strict CSP assets, idempotency, versions, audit, backup/restore, recovery, and privacy controls.

Honest limits

  • Not a financial ledger or accounting-system replacement.
  • Local mode uses HTTP on loopback; Docker/Compose and Kubernetes/Helm artifacts are source-ready, with runtime verification gated by CI and a real cluster.
  • The PostgreSQL adapter and deployment templates are implemented. Managed database HA, PITR, capacity, and failover are operator responsibilities and have not been proven in a deployed cluster.
  • Local named users and sessions exist; OIDC is specified but no provider adapter is configured.
  • Signed amd64/arm64 images are published to Docker Hub and GHCR. Real DNS/TLS, secret-manager integration, encrypted offsite backups, database failover, alerting, and restore rehearsal remain operator work.
  • No independent security audit has been performed.

Questions a business owner may ask

Straight answers about what Mosaic can do today and where an implementer is still needed.

Can I try it without an IT team?

Yes. The local evaluation needs Python 3.10+ and two commands. A production setup with PostgreSQL, backups, HTTPS, and multiple servers should be handled by a capable implementer.

Will it fit my type of shop?

Mosaic changes the blueprint for grocery, fashion, electronics, pharmacy, beauty, specialty retail, services, multiple stores, online channels, credit, expiry, warranty, and staff patterns.

Can it import my existing products, customers, or invoices?

Not yet. The current release exports blueprints and workspace data but does not include a product, customer, or invoice import tool. Migration scope must be planned separately.

Can different stores and staff have different access?

The blueprint models multi-store workflows and supports viewer, editor, and owner roles in tenant-isolated workspaces. It is not yet a complete store transaction ledger.

Can I use it for billing and accounting today?

No. Mosaic is a blueprint and configuration service, not a billing engine, financial ledger, or accounting replacement.

Does it calculate or file my taxes?

No. Its 22 source-linked tax packs guide configuration and flag missing facts. They are not filings, certification, legal advice, or tax advice. An accountant should confirm classifications and current rules.

What happens if the internet fails?

The local Python/SQLite version runs on the same machine and does not need the internet for normal use after download. A hosted or multi-store deployment depends on the network and infrastructure chosen by the operator.

Who owns the data?

In a self-hosted setup, the business controls its environment. Mosaic supports full blueprint JSON export, authenticated workspace export, backups, and confirmed tenant deletion.

How do backups, upgrades, and support work?

Local backup/restore commands and production runbooks are included. There is no promised managed support service. The business or its implementer owns upgrade testing, offsite backups, restore drills, monitoring, and incident response.

Should I use the simple or production version?

Use the two-command SQLite path to evaluate Mosaic. Docker Compose or Kubernetes/Helm with external PostgreSQL are for an implementer building a production environment.

Should my accountant or implementer be involved?

Yes for production deployment, data migration, accounting integration, and tax decisions. Mosaic reduces discovery work, but it does not replace professional review.

How much migration work is required?

It depends on current systems and data quality. Because automated business-data import is not included, mapping and migration must be scoped before a switch.

What does it cost?

The source is MIT licensed and the current release has no software licence fee. Hosting, database, implementation, migration, operations, and professional advice can still cost money.

What is complete today?

The guided interview, deterministic blueprint compiler, previews, exports, versioned workspaces, roles, audit and rollback, tax configuration layer, PostgreSQL adapter, and deployment packages are implemented and tested. A full operational sales, invoice, inventory, and accounting ledger is not.
